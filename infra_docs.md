# AWS Infrastructure Documentation

Last checked: 2026-07-13  
AWS account: `543698162562`  
Region: `us-east-1`  
Terraform directory: `terraform/`

This project is deployed as a single public Flask application on AWS ECS Fargate, backed by PostgreSQL on RDS. The app can be destroyed and recreated without preserving old data. To restore useful functionality after recreation, rebuild/push the container image, apply Terraform, then repopulate the database from the source scrapers.

Do not copy database passwords from Terraform state into this document. The database password is generated by Terraform and stored in AWS Secrets Manager.

## Recreate From Scratch

These steps recreate the app without preserving old database data.

### 1. Prerequisites

Install and configure:

```text
AWS CLI authenticated to account 543698162562
Terraform >= 1.6.0
Docker
PowerShell
```

Confirm identity:

```powershell
aws sts get-caller-identity
```

Expected account:

```text
543698162562
```

### 2. Decide on the Embedding Provider

Before applying Terraform, decide whether to match the live app or the current checked-in Terraform:

```text
Match current live/state behavior:
  RAG_EMBEDDING_PROVIDER=hash
  no RAG_EMBEDDING_MODEL required

Apply current checked-in Terraform:
  RAG_EMBEDDING_PROVIDER=bedrock
  RAG_EMBEDDING_MODEL=cohere.embed-english-v3
```

Using `bedrock` embeddings may improve semantic retrieval, but it requires Bedrock model access and adds Bedrock embedding API usage cost. The currently running service uses `hash`.

### 3. Create the ECR Repository First

The ECS task needs an image in ECR. Since Terraform creates both ECR and ECS, the cleanest bootstrap is to create only the ECR repository first:

```powershell
cd terraform
terraform init
terraform apply -target=aws_ecr_repository.app
cd ..
```

### 4. Build and Push the App Image

Use the existing script:

```powershell
.\build_and_push.ps1 -Region us-east-1 -RepositoryName contract-aggregator-tool -PushLatest
```

The ECS task uses the `latest` tag by default. The script builds from `Dockerfile` and pushes to:

```text
543698162562.dkr.ecr.us-east-1.amazonaws.com/contract-aggregator-tool
```

### 5. Apply the Rest of Terraform

```powershell
cd terraform
terraform apply
terraform output
cd ..
```

Important outputs:

```text
app_url
ecr_repository_url
ecs_cluster_name
db_endpoint
db_secret_name
```

After apply, check ECS and the app:

```powershell
aws ecs describe-services --cluster contract-aggregator-tool --services contract-aggregator-web --region us-east-1
Invoke-RestMethod -Uri "$(terraform -chdir=terraform output -raw app_url)/health"
```

A brand-new database will not have the `postings` table until ingestion creates the schema. Before ingestion, `/health` may return `db_connected=false` because the table is missing. After ingestion creates the schema, it should report `db_connected=true`; if no records were inserted, `total_postings_in_db` will be `0`.

## Reload Fresh Data

Terraform does not create a scheduled ingestion job. Data is loaded by Python scripts in the app image:

```text
run_all.py       loads SAM.gov, Acquisition Gateway, and Virginia eVA
run_sam_only.py  loads SAM.gov only
```

Because RDS is private and only accepts traffic from the ECS web security group, run ingestion from inside ECS, not from a local laptop.

Example one-off ECS task after Terraform apply:

```powershell
aws ecs run-task `
  --cluster contract-aggregator-tool `
  --launch-type FARGATE `
  --task-definition contract-aggregator-tool `
  --region us-east-1 `
  --network-configuration "awsvpcConfiguration={subnets=[subnet-001c152def05728b7,subnet-07429104a55a0dfed],securityGroups=[sg-0977ac573dd73aa4d],assignPublicIp=ENABLED}" `
  --overrides '{"containerOverrides":[{"name":"web","command":["python","run_all.py"]}]}'
```

After a full destroy/recreate, subnet IDs and security group IDs may change. Use the current values from AWS Console or AWS CLI before running the command. `aws ecs describe-services` shows the ECS service network configuration after the service exists; `aws ec2 describe-security-groups --filters Name=group-name,Values=contract-aggregator-web` can find the web security group.

SAM.gov ingestion requires `SAM_API_KEY`. That key is not currently managed by Terraform and is not present in the live ECS task definition. To include SAM.gov records in a one-off ingestion run, pass `SAM_API_KEY` as a container environment override or add a proper secret-managed configuration path before running ingestion:

```powershell
--overrides '{"containerOverrides": [{"name": "web", "command": ["python", "run_all.py"], "environment": [{"name": "SAM_API_KEY", "value": "<your-sam-api-key>"}]}]}'
```

Acquisition Gateway and eVA do not require this SAM key.

The app database schema is created by `db.py::setup_database()` when ingestion runs. The app itself also expects the `postings` table to exist for `/health` to count postings.

## Runtime Behavior After Rebuild

The app serves:

```text
/                 frontend from index.html and static files
/health           health status and DB posting count
/api/opportunities
/api/chat         RAG-backed chat endpoint
```

The RAG index is local to the running container filesystem. It is built from database records on demand and is not stored in S3, EFS, or RDS. Losing it during destroy or task replacement is fine; it will rebuild from the database.

There is no persistent file storage volume in ECS.

## Destroy Notes

The current Terraform configuration intentionally allows destructive teardown:

```text
RDS deletion_protection=false
RDS skip_final_snapshot=true
CloudWatch retention=7 days
No persistent ECS volume
No remote Terraform backend
```

Expected data loss:

```text
RDS database contents
ECS task ephemeral files
CloudWatch logs after log group deletion or retention expiry
RAG local index files
```

Potential destroy/recreate caveats:

```text
ECR repository deletion may fail if images remain because force_delete is not set.
Secrets Manager may schedule secret deletion; recreating the same secret name can be blocked while deletion is pending.
Default VPC resources are managed by Terraform here; be careful if other projects use the same default VPC/subnets.
Terraform state is local, so preserve the Terraform source files and this documentation even if state changes after destroy.
```

## What Is Not Currently Managed

These are not present in the current Terraform:

```text
HTTPS / ACM certificate
Route 53 DNS
Autoscaling
NAT gateway
ECS scheduled task for ingestion
RDS backups or snapshots
RDS encryption
Remote Terraform state backend
SAM_API_KEY storage
API_SHARED_SECRET for write routes
```

`proxy.py` supports `API_SHARED_SECRET` for protecting write routes, but the ECS task definition does not currently set it. Without that variable, write routes fail open with a warning in application logs.
